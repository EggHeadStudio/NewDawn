# Architecture

- `src/main.ts` still owns scene orchestration, browser controls, UI and IndexedDB transactions. Gameplay updates use a 30 Hz accumulator with capped elapsed time, but simulation is still coupled to Three.js objects, input, camera and UI; this is not yet an authoritative server-ready simulation.
- `src/planet.ts` defines a 3,072 by 1,536-unit coordinate model, periodic longitude, reflected polar coordinates with a half-turn, equivalent-position projection and spherical-coordinate terrain sampling. It is a flat gameplay projection rather than spherical geometry or spherical-distance physics.
- `src/world.ts` retains the original starter terrain and resource layout, blends into generated terrain beyond it, incrementally loads 24-unit chunks, unloads and disposes distant chunks, and persists terrain edits and depleted nodes by normalized coordinate. Loaded chunks form a bounded cache; ground cover is instanced, while trees and resource props are not. Periodic coordinate rebasing limits rendering precision loss.
- `src/appearance.ts` defines serializable appearances; `src/characters.ts` provides the procedural fallback. `src/authored-character.ts` loads local Quaternius glTF prototypes and clips asynchronously, clones skinned scenes using `SkeletonUtils`, and runs per-instance animation mixers. The player, Mira, raiders and `src/character-preview.ts` use this path; the other enemies retain the procedural hierarchy in `src/enemies.ts`. Shared prototype geometry and textures remain cached, while cloned skeletons and tinted materials are disposed per character. Separate head, outfit and hair skeletons are animated in parallel. There is no character LOD; not all saved appearance values have matching authored assets.
- `src/wildlife.ts` holds serializable animal state and simulation; `src/animal-assets.ts` creates and animates the corresponding procedural models. Population and simulation remain island-wide rather than chunk-based.
- `src/camera.ts` contains camera-relative movement, angle interpolation and zoom bounds; the camera and input orchestration still live in `main.ts`.
- `src/gameplay.ts` contains inventory costs, crafting, building checks and day/night helpers.
- `src/economy.ts` defines deposit types and mineral inventory; `src/world.ts` generates finite three-hit deposits independently of legacy resource nodes, persists per-deposit progress by planetary coordinate and excludes existing saved construction. `src/smelting.ts` defines atomic fuel/input reservation and timed production; workstation state and the iron-pickaxe upgrade are orchestrated in `main.ts`. Other workstations, technology and most uses for the materials are not implemented.
- `src/construction.ts` defines sparse wooden structural records, grid snapping, occupancy, costs/refunds, door collision, floor/stair surfaces and bounded perimeter flood-fill. `src/construction-render.ts` batches pieces in instanced meshes and handles door animation and per-roof visibility. Placement, room reconciliation, persistence and simple player/NPC/rover collision are still orchestrated in `main.ts`. Structures are currently stored in one save array and rendered globally, not streamed by chunk; stair collision is approximate and there is no structural support simulation.
- `src/npc.ts` contains the survivor's basic activity selection and movement helper; scene-level task execution is still in `main.ts`.
- `src/power.ts` computes distance-linked electrical components, wind generation, battery storage and lamp consumption.
- `src/calendar.ts` supplies deterministic season and daily weather selection; `src/effects.ts` renders lightweight particles.
- `src/save.ts` validates version 1–8 save shapes before loading. A version 1–5 save is copied to `pre-planet-backup`, a version 1–6 save to `pre-construction-backup`, and a version 1–7 save to `pre-economy-backup` in IndexedDB before loading. Version 8 adds mineral inventory, deposit progress, ingots, the upgrade and active smelter jobs while retaining prefab and structural records. Main-menu JSON export and validated import are available; import backs up the replaced primary slot. Browser I/O remains in `main.ts`; enemies and projectiles are transient.
- `src/pwa.ts` handles optional installation and user-approved update activation. `vite.config.ts` emits a versioned service worker which precaches a matching shell, hashed assets and bundled character models/textures; saves remain in IndexedDB. The character files add approximately 20 MB to the precache. Multi-tab coordination is not yet implemented.
- `src/style.css` styles the interface; `public/` contains the PWA shell; `.github/workflows/deploy.yml` deploys the built Pages artifact.

This is not yet a multiplayer-ready simulation boundary or a complete spherical planet. Entity state, distant NPC/wildlife simulation, seam-aware navigation and polar gameplay require further separation and verification.
